# AI Agent Workflow 프레임워크 설계

AI Agent의 동작을 그래프로 정의하고 실행하는 프레임워크의 설계 문서입니다. 은행 챗봇의 이체, 대출, 카드 업무가 사례로 등장하지만, 설계하는 대상은 챗봇이 아니라 여러 팀의 Agent가 공통으로 사용하는 기반입니다.

설계서 본문은 [00.architecture.md](00.architecture.md)에 있습니다.

## 1. 이 설계가 해결하는 문제

LLM에게 Agent의 동작을 자유롭게 맡기면 세 가지 문제가 생깁니다. 같은 입력에도 실행 경로가 달라져 결과를 재현할 수 없고, 어디까지 진행했는지 알 수 없어 장애가 나면 이어 갈 수 없으며, 돈을 쓰거나 데이터를 바꾸는 행동을 통제할 수 없습니다.

이 설계는 준법감시실이 제시한 두 가지 조건을 프레임워크의 구조로 보장하는 것을 목표로 합니다.

1. 돈이 나가거나 고객의 권리가 바뀌는 거래는 반드시 정해진 통제 절차를 거친다. LLM이 단독으로 실행하는 일은 없다.
2. 처리 도중에 시스템이 멈추거나 재배포되어도 요청이 사라지거나 두 번 실행되지 않는다.

## 2. 여섯 가지 기본 개념

프레임워크 전체가 다음 여섯 개념 위에 서 있습니다. 앞의 셋은 그래프를 정의하는 개념이고, 뒤의 셋은 그래프를 실행하는 개념입니다.

| 개념 | 설명 |
|---|---|
| State | 그래프 하나가 처음부터 끝까지 공유하는 데이터. 키마다 합치는 규칙을 선언한다 |
| Node | State를 읽고, 필요하면 모델이나 도구를 부르거나 응답을 기다린 뒤, 바뀐 부분만 돌려주는 함수 |
| Edge | 다음 노드를 정하는 규칙. 고정, 조건부, 퍼뜨리기, 되돌아가기가 있다 |
| Checkpoint | 노드가 끝날 때마다 저장하는 State의 복사본 |
| Pause | 노드가 사람이나 외부 시스템의 응답을 기다리기 위해 실행을 멈추는 연산 |
| Middleware | 노드 실행, 모델 호출, 도구 호출을 감싸서 공통 처리를 끼워 넣는 함수 |

## 3. 핵심 설계 결정

- 그래프는 코드로 작성하고, `compile()`이 구조를 데이터로 뽑아 정적으로 검사합니다. 되돌릴 수 없는 도구 앞에 사람의 확인이 없는 그래프는 만들어지지 않습니다.
- 실행기는 서버가 아니라 라이브러리입니다. 별도의 스케줄러, 작업 큐, 작업자 프로세스를 두지 않고, 여러 서버가 같은 저장소를 공유합니다.
- 노드가 끝날 때마다 체크포인트를 저장하고, 중단된 run은 마지막 체크포인트부터 이어 갑니다.
- 바깥을 바꾸는 도구 호출에는 영수증 번호(멱등성 키)를 자동으로 붙여, 다시 실행해도 한 번만 실행되게 합니다.
- 사람, 외부 시스템, 정해진 시각을 기다리는 일은 모두 `pause` 하나로 표현하며, 기다리는 동안에는 아무 자원도 붙잡지 않습니다.
- 도구는 `none`, `reversible`, `irreversible`의 세 등급으로 나누고, 모델은 되돌릴 수 없는 도구를 직접 고를 수 없습니다.
- 되돌릴 수 없는 도구는 실행 직전에 "승인한 내용과 실행할 내용이 같은가"를 한 번 더 확인합니다.
- 추적, 비용 한도, 권한 검사, 승인 확인, 마스킹은 플랫폼 필수 미들웨어로 두며, Agent 개발자가 끌 수 없습니다.
- 저장소는 인터페이스로만 정의하므로, 관계형 DB, 문서 DB, 키-값 저장소, 파일, 메모리 가운데 무엇으로든 구현할 수 있습니다.

## 5. 읽는 방법

각 장은 운영 중에 벌어진 장면으로 시작해서, 그 장면이 프레임워크에 요구하는 것을 설명하고, "이 장의 결정과 그 대가"로 끝납니다. 설계의 이유가 궁금하면 본문을 처음부터 읽고, 사양만 필요하면 별첨 A를 바로 읽으면 됩니다.

코드는 특정 언어에 매이지 않는 의사코드로 적었습니다. 역할은 프레임워크를 만드는 플랫폼팀과, 프레임워크로 Agent를 만드는 Agent 개발자 둘로만 나눕니다.
