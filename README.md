# AI Agent Workflow 프레임워크 설계

AI Agent의 동작을 workflow로 정의하고 실행하는 프레임워크를 **만드는 쪽의 설계** 문서입니다. 어떤 요구사항이 있는지, 그 요구사항을 만족하려면 어떤 구성 요소가 필요한지, 각 구성 요소가 어떻게 동작하는지, 무엇을 고려해야 하는지를 다룹니다.

설계서 본문은 [00.architecture.md](00.architecture.md)에 있습니다.

## 1. 이 설계가 해결하는 문제

LLM에게 Agent의 동작을 자유롭게 맡기면 결과를 재현할 수 없고, 중단되면 이어 갈 수 없으며, 사람이나 외부 시스템을 기다릴 수 없고, 돈을 쓰거나 데이터를 바꾸는 행동을 통제할 수 없습니다.

이 프레임워크는 Agent가 할 수 있는 일의 순서와 분기를 workflow로 미리 정의하고, LLM은 workflow 안의 정해진 노드에서 정해진 형식으로만 판단하게 합니다. 실행 엔진은 노드마다 상태를 저장하며 실행하므로 중단되어도 이어 갈 수 있고, 모든 모델 호출과 도구 호출은 프레임워크의 통제 장치를 거칩니다.

## 2. 기본 개념

| 개념 | 설명 |
|---|---|
| workflow | Agent의 동작을 노드와 에지로 정의한 방향 그래프. 반복을 허용한다 |
| 노드와 에지 | 노드는 처리 단계 하나이고, 에지는 다음에 갈 노드를 정한다. 분기, 병렬, 반복은 모두 에지로 표현한다 |
| State | run 하나가 실행되는 동안 노드들이 함께 쓰는 데이터. 노드는 바뀐 키만 돌려준다 |
| workflow 명세 | compile이 코드에서 뽑아낸 구조. 실행하지 않고도 검사하고 그림으로 그릴 수 있다 |
| run과 체크포인트 | run은 workflow를 한 번 실행한 것이고, 체크포인트는 노드가 끝나거나 멈출 때마다 저장하는 진행 기록이다 |
| 대기와 재개 | 노드가 사람, 외부 시스템, 정해진 시각을 기다리면 run을 멈추고, 응답이 오면 이어 간다. 기다리는 동안 자원을 쓰지 않는다 |
| 도구의 등급 | `none`, `reversible`, `irreversible`. 되돌릴 수 없는 도구에 가장 강한 통제를 건다 |
| 미들웨어 | 실행, 노드, 모델 호출, 도구 호출의 길목에 공통 처리를 끼워 넣는 함수 |

## 3. 핵심 설계 결정

- workflow는 코드로 작성하고, compile이 구조를 workflow 명세로 뽑아 정적으로 검사합니다. 되돌릴 수 없는 도구 앞에 사람의 확인 노드가 없는 workflow는 만들어지지 않습니다.
- 실행기는 서버가 아니라 라이브러리입니다. 여러 응용 서버가 같은 저장소를 공유하고, 한 run은 잠금으로 한 서버만 실행합니다.
- 노드가 끝날 때마다 체크포인트를 저장하고, 중단된 run은 마지막 체크포인트부터 이어 갑니다. 재개할 때는 멈춘 노드를 처음부터 다시 실행합니다.
- 바깥을 바꾸는 도구 호출에는 멱등성 키를 자동으로 붙여, 다시 실행해도 외부 변경은 한 번만 일어나게 합니다.
- 모든 기다림은 대기 요청 하나(`wait`)로 표현하고, 응답이 오면 그 호출이 실행을 다시 시작합니다. 프레임워크가 스스로 지켜보는 것은 기한뿐입니다.
- 모델은 도구를 고르기만 하고 실행은 다른 노드가 합니다. 모델이 고를 수 있는 도구에 되돌릴 수 없는 도구는 들어갈 수 없습니다.
- 되돌릴 수 없는 도구는 실행 직전에 "승인한 내용과 실행할 내용이 같은가"를 한 번 더 확인합니다.
- 추적, 비용 한도, 권한, 승인 확인, 마스킹은 플랫폼 필수 미들웨어이며, Agent 개발자가 끌 수 없습니다. workflow는 run에 고정하고, 통제는 진행 중인 run에도 최신을 적용합니다.
- 저장소는 인터페이스로만 정의합니다. 기본 구현은 관계형 DB이고, 다른 구현은 적합성 시험을 통과하면 쓸 수 있습니다.

## 5. 읽는 방법

설계의 중심은 3장(workflow를 어떻게 정의하는가)과 4장(어떻게 실행하는가)입니다. 처음 읽는다면 0장의 용어와 2.3절의 예시 workflow를 먼저 보면 이후 장을 따라가기 쉽습니다. 3장부터 7장까지는 각 장 끝의 "이 장의 결정 요약"에 결정, 근거, 대가가 정리되어 있고, 인터페이스만 필요하면 부록 A를 바로 읽으면 됩니다.

코드는 특정 언어에 매이지 않는 의사코드로 적었고, 특정 제품 이름은 쓰지 않았습니다. 역할은 프레임워크를 만드는 플랫폼팀과, 프레임워크로 Agent를 만드는 Agent 개발자 둘로만 나눕니다.
